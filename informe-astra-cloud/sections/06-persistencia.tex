\chapter{Uso de bases de datos}
\section{PostgreSQL}
El proyecto usa distintas bases de datos según el tipo de información que maneja cada servicio; este enfoque se conoce como persistencia políglota. PostgreSQL se usa en Identity y Catalog. Identity guarda \texttt{users}; Catalog guarda \texttt{movie}, \texttt{genre}, \texttt{artist}, las tablas puente \texttt{movie\_genre} y \texttt{movie\_artist}, fuentes de video y subtítulos. Las relaciones N:M entre películas, géneros y artistas se materializan mediante dichas tablas puente, y Flyway mantiene las versiones del esquema.
El modelo entidad-relación final de Catalog se presenta en la Figura~\ref{fig:er-catalog-final}.
\begin{figure}[H]\centering\includegraphics[width=\textwidth,height=.76\textheight,keepaspectratio]{figures/version_final_er_catalog.jpeg}\caption{Modelo entidad-relación final del Catalog Service en PostgreSQL.}\label{fig:er-catalog-final}\end{figure}
\section{MySQL}
Community usa MySQL para usuarios, clubes, membresías, salas y participantes. La tabla \texttt{memberships} materializa la relación N:M entre usuarios y clubes. Las salas guardan el anfitrión y, si corresponde, el club; \texttt{watch\_participants} registra sus participantes. El campo \texttt{watch\_rooms.movie\_id} es una referencia lógica hacia Catalog y no una clave foránea física entre MySQL y PostgreSQL.
\begin{figure}[H]\centering\includegraphics[width=\textwidth,height=.76\textheight,keepaspectratio]{../comunity.jpeg}\caption{Diagrama ER actualizado del Community Service en MySQL.}\label{fig:er_community_actualizado}\end{figure}
\section{MongoDB}
Interaction usa MongoDB para \texttt{reviews}, \texttt{likes}, \texttt{watchlists} y \texttt{watch\_history}. La implementación oficial de \url{https://github.com/dado4cs/interaction-service} define \texttt{movie\_id} como \texttt{String} (referencia lógica al UUID de Catalog) y \texttt{user\_id} como \texttt{Integer} (referencia lógica a Community). Los documentos incluyen fechas, snapshots embebidos de película y usuario y los campos específicos de cada interacción. El snapshot de película conserva \texttt{id}, \texttt{title} y \texttt{poster\_url}; el de usuario, \texttt{id}, \texttt{username}, \texttt{display\_name} y \texttt{avatar\_url}. Estos identificadores no son claves foráneas físicas de MongoDB.
